# 라이어스 배팅 (Liar's Batting)

숫자야구 규칙에 거짓말/신뢰-의심/영웅 능력을 더한 심리전 대전 게임입니다. AI와 대전하거나, 온라인으로 랜덤/친구 매칭을 통해 대전할 수 있습니다.

이 문서는 **Unity를 처음 써보는 팀원**도 그대로 따라 하면 실행까지 갈 수 있도록 자세히 적었습니다. 순서대로 진행해주세요.

---

## 1. 사전 설치 (한 번만)

### 1-1. Git
- https://git-scm.com/downloads 에서 설치 (기본 옵션 그대로 Next만 눌러도 됩니다)

### 1-2. Unity Hub
- https://unity.com/download 에서 Unity Hub 설치
- Unity 자체가 아니라 "여러 버전의 Unity 에디터를 관리해주는 런처"입니다. 실제 에디터는 다음 단계에서 Hub 안에서 설치합니다.

### 1-3. Unity 에디터 6000.6.0f1 설치
이 프로젝트는 **정확히 6000.6.0f1** 버전으로 만들어졌습니다. 버전이 다르면 프로젝트가 안 열리거나 미묘한 오류가 날 수 있으니 꼭 같은 버전을 맞춰주세요.

1. Unity Hub 실행 → 왼쪽 메뉴 **Installs** 탭 → **Install Editor**
2. 목록에 6000.6.0f1이 안 보이면 우측 상단 **Archive** (또는 "다른 버전 찾기") 로 들어가서 검색:
   `https://unity.com/releases/editor/whats-new/6000.6.0` 페이지에서 "Unity Hub에서 설치" 링크를 눌러도 Hub가 자동으로 인식합니다.
3. 모듈(Modules) 선택 화면에서는 최소한 아래를 체크:
   - **Microsoft Visual Studio Community** (아직 IDE가 없다면 체크 — 코드 편집기 겸 컴파일러)
   - 본인 OS에 맞는 빌드 타겟 (Windows면 특별히 추가 체크 안 해도 에디터 실행/테스트는 가능합니다)
4. 설치가 끝날 때까지 대기 (용량이 커서 시간이 꽤 걸립니다)

### 1-4. IDE (코드 편집기)
- 위 3번에서 Visual Studio Community를 함께 설치했다면 별도 설치 불필요합니다.
- 이미 다른 에디터(Rider, VS Code 등)를 쓰고 싶다면 그것도 무방합니다.

## 2. 프로젝트 받아오기 (클론)

원하는 폴더에서 터미널(Git Bash, PowerShell 등)을 열고:

```bash
git clone https://github.com/Rokmc1292/Game_project.git
```

완료되면 `Game_project` 폴더가 생성됩니다.

> 이미 클론해둔 상태에서 팀원이 올린 최신 변경사항만 받아오고 싶다면:
> ```bash
> git pull
> ```

## 3. Unity Hub에서 프로젝트 열기

1. Unity Hub 실행 → 왼쪽 메뉴 **Projects** 탭 → **Add** (또는 "Open") 버튼
2. 방금 클론한 `Game_project` 폴더를 선택
3. 목록에 프로젝트가 추가되면 클릭해서 열기
   - Hub가 "이 프로젝트는 6000.6.0f1이 필요합니다" 라고 표시하면, 1-3에서 설치한 버전을 그대로 선택하면 됩니다.
4. **처음 여는 경우 몇 분 정도 걸립니다.** Unity가 패키지를 내려받고 모든 스크립트를 컴파일하는 중이니, 상태 표시줄(우측 하단 진행바)이 다 찰 때까지 기다려주세요.
5. 다 열리면 Unity 에디터 창이 나타나고, 하단 **Console** 탭에 빨간 에러가 없는지 확인합니다. (노란 경고는 무시해도 괜찮습니다)

## 4. 실행해보기 (Play)

이 프로젝트는 씬(Scene)에 아무것도 미리 배치해두지 않았습니다. 게임 UI/로직 전체가 `GameBootstrap.cs` 코드에서 실행 시점에 자동으로 생성되기 때문에 **어떤 씬을 열어도 상관없습니다.**

1. 상단 **Project** 창에서 `Assets/Scenes/SampleScene.unity` 를 더블클릭해서 엽니다 (이미 열려 있다면 생략)
2. 화면 상단 중앙의 ▶ **Play 버튼** 클릭
3. 닉네임 입력 화면이 뜨면 정상 실행된 것입니다. 아무 닉네임이나 입력하고 진행해보세요.
4. 메인 메뉴에서 **AI 매칭**을 눌러보면 네트워크 없이 바로 혼자서 플레이해볼 수 있습니다.

## 5. 온라인 매칭(랜덤 매칭/친구 매칭) 테스트하기 — ParrelSync

온라인 매칭은 상대방 클라이언트가 있어야 테스트할 수 있습니다. 팀원과 각자 실행해서 테스트할 수도 있지만, **혼자서도 PC 한 대로 테스트**할 수 있도록 `ParrelSync`라는 에디터 확장이 이미 프로젝트에 설치되어 있습니다.

1. Unity 에디터 상단 메뉴 **ParrelSync → Clones Manager** 클릭
   - 메뉴가 안 보인다면 하단 Console에 에러가 있는지 먼저 확인하세요 (컴파일이 안 끝났으면 메뉴가 생성되지 않습니다).
2. **Create new clone** 클릭 → 프로젝트 폴더 옆에 `Game_project_clone` 폴더가 자동으로 생성됩니다.
3. 클론이 만들어지면 **Open in New Editor** 클릭 → 두 번째 Unity 에디터 창이 열립니다.
4. 이제 원본 창과 클론 창, **양쪽 다 Play** 버튼을 눌러 각각 다른 닉네임으로 접속됩니다. (클론은 자동으로 닉네임 저장 위치가 분리되어 있어 원본과 겹치지 않습니다)
5. 한쪽에서 "랜덤 매칭"을 누르고 다른 쪽에서도 "랜덤 매칭"을 누르면 서로 매칭되어 대전이 시작됩니다. "친구 매칭"은 서로의 닉네임을 알고 있어야 초대할 수 있습니다.

> ParrelSync 클론 폴더(`Game_project_clone`)는 Git 저장소 폴더 **바깥**에 생성되므로 커밋될 걱정 없이 자유롭게 만들고 지워도 됩니다.

## 6. 온라인 매칭 관련 — Firebase 설정 이해하기

### 6-1. 어떻게 동작하나
온라인 매칭(랜덤 매칭/친구 매칭)은 Google의 **Firebase Firestore**라는 클라우드 데이터베이스를 통해 두 클라이언트가 서로의 턴/상태를 주고받는 구조입니다. 보통 Firebase는 전용 SDK를 설치해서 쓰지만, 이 프로젝트는 **네이티브 SDK 없이 REST API(그냥 HTTP 요청)로 직접 통신**합니다 — 그래서 팀원 누구든 SDK를 따로 설치하거나 Firebase 콘솔에 가입할 필요가 전혀 없습니다.

- 접속 정보(프로젝트 ID, API 키)는 `Assets/_Project/Scripts/Network/FirebaseConfig.cs` 한 파일에 들어 있고, 이미 저장소에 커밋되어 있습니다.
- 클론받는 순간 팀원 전원이 **같은 Firestore 프로젝트(`liarsbatting`)를 공유**하게 됩니다. 즉, 팀원 A와 팀원 B가 각자 실행해도 서로 매칭이 잡힙니다 (같은 DB를 보고 있으니까요).
- 어떤 데이터가 오가는지: 매치 문서 하나(`matches/{matchId}`)에 턴 정보, 서로에게 알려준 (거짓일 수도 있는) 결과, 공개된 자리 숫자만 기록됩니다. **각자의 진짜 비밀번호 4자리는 절대 서버에 올라가지 않습니다** — 실제 판정은 각자 클라이언트에서 로컬로 계산하고, 서버에는 "결과"만 적습니다.

### 6-2. API 키가 코드에 그대로 적혀 있는데 괜찮은 건가요?
`FirebaseConfig.cs`의 `ApiKey`는 이른바 **Firebase 웹 API 키**로, 서버의 진짜 비밀키(secret key)와는 다릅니다. Firebase 공식 문서에서도 이 키는 클라이언트 앱에 그대로 포함되는 것을 전제로 설계되어 있고, 보안은 이 키가 아니라 **Firestore 보안 규칙(Security Rules)**으로 한다고 안내합니다. 그래도 다음은 지켜주세요:

- 이 저장소를 나중에 **public으로 바꾸거나 다른 곳에 공유할 계획이 있다면** 미리 얘기해주세요 (규칙을 더 조여야 할 수도 있습니다).
- 실제 서비스 비밀키(예: Firebase Admin SDK의 서비스 계정 JSON 같은 것)는 **절대 이 방식으로 커밋하면 안 됩니다.** 지금 프로젝트엔 그런 키가 없지만, 나중에 서버 기능을 추가한다면 그때는 `.gitignore`에 추가하고 팀원끼리 별도로 공유해야 합니다.

### 6-3. 보안 규칙 (`firestore.rules`)
저장소 루트의 `firestore.rules`가 이 게임용 Firestore 보안 규칙입니다. **Firebase 콘솔 → Firestore Database → 규칙 탭**에 내용을 그대로 붙여넣고 **게시**하면 적용됩니다. (이 파일을 고쳐도 콘솔에 다시 붙여넣기 전까지는 서버에 반영되지 않습니다.)

- 게임이 쓰는 컬렉션 5개(`players`, `matches`, `matchQueue`, `invites`, `matchPresence`)만 열려 있고, 그 밖의 경로는 모두 막힙니다.
- 각 문서에는 게임이 실제로 쓰는 필드만, 정해진 형식과 크기로만 저장할 수 있습니다.
- 전적은 한 번 저장할 때 1승 또는 1패씩만 늘어날 수 있고, 레벨은 내려갈 수 없습니다.
- **한계:** 로그인이 없어서 "누가" 쓰는지는 구분하지 못합니다. API 키를 아는 사람이 다른 플레이어의 문서를 고치거나 지우는 것은 막을 수 없습니다. 이것까지 막으려면 Firebase 익명 로그인(Anonymous Auth)을 붙이고, 문서마다 주인의 uid를 저장해서 규칙에서 확인해야 합니다.
- 게임 코드에 새 필드나 컬렉션을 추가하면 **이 규칙에도 추가**해야 합니다. 빠뜨리면 그 저장이 서버에서 거부됩니다.

### 6-4. 팀원이 해야 할 일
**없습니다.** 클론 → Unity Hub에서 열기 → Play 누르면 온라인 매칭까지 바로 동작합니다. Firebase 콘솔 가입, 프로젝트 생성, 키 발급 같은 절차는 전부 필요 없습니다.

## 7. 프로젝트 구조 한눈에 보기

```
Assets/_Project/Scripts/
├─ Core/          게임 규칙 데이터 (숫자야구 판정, 상태 등) — UnityEngine 의존 없는 순수 C#
├─ AI/            AI 상대 로직 (추리 알고리즘, 영웅 능력 판단)
├─ Network/       Firestore 통신, 온라인 매칭/턴 프로토콜
└─ Presentation/  화면 UI 전체 (전부 코드로 생성, 씬/프리팹 없음)
```

버그를 찾거나 기능을 추가할 때 대부분 `Presentation/GameBootstrap.cs` (화면 흐름 전체를 담당) 를 보게 될 겁니다.

## 8. 협업 시 주의사항 (Git)

- **`Library/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln` 폴더/파일은 커밋하지 마세요.** 이미 `.gitignore`에 등록되어 있어서 `git status`에도 안 뜰 겁니다. (Unity가 매번 새로 만들어내는 캐시/자동생성 파일들이라 커밋해도 의미가 없고, 용량만 커집니다)
- 씬/프리팹은 텍스트(YAML) 형식으로 저장되도록 이미 설정되어 있어서(`Force Text`) 깃에서 diff가 보이긴 하지만, **같은 씬이나 프리팹을 여러 명이 동시에 수정하면 충돌이 매우 나기 쉽습니다.** 이 프로젝트는 씬을 거의 안 쓰므로 (전부 코드 UI) 이 문제는 드물지만, `.meta` 파일도 항상 스크립트와 같이 커밋해주세요 (Unity가 자동으로 만들어줍니다. 지우거나 무시하면 안 됩니다).
- 커밋 전에 Unity Console에 빨간 에러가 없는지 한 번 확인하는 습관을 들이면 좋습니다.

## 9. 자주 겪는 문제 (트러블슈팅)

**Q. Unity Hub에서 프로젝트를 열려니 "버전이 없다"고 뜬다.**
→ 1-3 단계대로 정확히 6000.6.0f1을 설치하세요. Hub가 자동으로 설치 여부를 물어보기도 합니다.

**Q. 처음 프로젝트를 열었는데 Console에 에러가 우수수 뜬다.**
→ 대부분 아직 백그라운드에서 패키지 설치/컴파일이 끝나지 않은 상태입니다. 하단 진행바가 끝날 때까지 잠시 기다렸다가 다시 확인하세요. 그래도 남아있으면 상단 메뉴 `Assets → Reimport All` 을 시도해보세요.

**Q. 상단 메뉴에 `ParrelSync`가 안 보인다.**
→ 컴파일이 아직 안 끝났거나(Console 우측 하단 회전 아이콘 확인) 에러가 있어서 스크립트가 컴파일되지 않은 상태입니다. 에러를 먼저 해결하세요.

**Q. 히스토리 영역에서 마우스 스크롤이 안 된다.**
→ 스크롤하려는 영역(마우스 커서) 위에 정확히 커서가 있어야 합니다. New Input System 기반으로 직접 마우스 휠 입력을 읽고 있어서, 커서가 그 영역 밖에 있으면 반응하지 않습니다.

**Q. 랜덤 매칭이 계속 안 잡힌다.**
→ 상대 쪽(팀원 PC 혹은 ParrelSync 클론)도 같은 시점에 "랜덤 매칭"을 눌러 대기 중이어야 합니다. 한쪽만 켜져 있으면 매칭 상대가 없어서 계속 기다리는 게 정상입니다.
